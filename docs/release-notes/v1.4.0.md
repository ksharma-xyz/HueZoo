# Huezoo v1.4.0 — Release Notes

Store copy for the 1.4.0 release. Paste as-is.

- **Android** — versionCode 115, tag `v1.4.0-RC2`, currently on the Play internal track.
- **iOS** — build 32, tag `v1.4.0-RC2`, currently on TestFlight.

> **Scope.** These notes cover 1.3.0 **and** 1.4.0. Production had not received
> 1.3.0 on either platform — the App Store is still on 1.2.0 (see below), and
> 1.3.0 on Play reached the internal track only, with no `v1.3.0` tag or GitHub
> release cut. So the 1.3.0 billing fixes are announced here for the first time.
>
> Color Memory Match (Game 6) is deliberately unmentioned:
> `DebugFlags.colorMemoryEnabled` is `false` in release builds, so production
> users cannot reach it.

## Why iOS jumps 1.2.0 → 1.4.0

The App Store never received a 1.3.0. `Fastfile#build_release` reads
`MARKETING_VERSION` from `iosApp/Configuration/Config.xcconfig`, but
`release-1-cut.yml` was bumping `iosApp/iosApp/Info.plist` — a file the build
ignores, because the project sets `GENERATE_INFOPLIST_FILE = YES` and Xcode
regenerates it from build settings at archive time. The xcconfig sat at 1.2.0
from `f05a78e` onward, so the 1.3.0 and 1.4.0 iOS uploads both went out
labelled 1.2.0, separated only by build number.

Fixed in #13 (this release branch) and #14 (the cut workflow, plus a pre-cut
guard that aborts if the Android and iOS versions disagree).
